# Fly-in

日本語翻訳版です。英語の提出版は[`README.md`](README.md)にあります。

## 説明

Fly-inは、ターン制のドローン経路シミュレーションです。ゾーンと双方向接続を含むマップを読
み込み、移動コストと容量制限を守りながら、すべてのドローンを開始ハブから終了ハブへ届ける
経路を計画します。

プログラムは、normal、priority、restricted、blockedゾーンを処理します。normalとpriority
ゾーンへ入るには1ターン、restrictedゾーンへ入るには2ターンかかり、blockedゾーンには入れ
ません。ゾーン容量と無向接続の容量は、関係する各ターンで適用されます。開始ハブと終了ハブ
の容量は無制限です。

主な目的は、ゾーンまたは接続の競合を発生させず、実用上できるだけ少ないターンでシミュレー
ションを完了することです。

## 実行方法

### 必要環境

- Python 3.10以降
- [uv](https://docs.astral.sh/uv/)
- 任意のPygame表示を使用する場合は、グラフィカルデスクトップ環境

### インストール

アプリケーションと開発用依存関係をインストールします。

```bash
make install
```

### シミュレーションの実行

同梱のサンプルマップを実行します。

```bash
make run
```

特定のマップを実行します。

```bash
make run MAP=maps/easy/01_linear_path.txt
```

同等の直接実行コマンドは次のとおりです。

```bash
uv run python fly_in.py maps/easy/01_linear_path.txt
```

### 視覚的表現

任意のPygameネットワーク表示を開きます。

```bash
make visual MAP=maps/easy/01_linear_path.txt
```

ビジュアライザーは、マップ座標上にゾーンとその接続を描き、各ドローンを現在のゾーンに表示
します。restrictedゾーンへ入る2ターン移動中は、ドローンを接続上に表示します。表示は1秒
ごとにシミュレーション状態を自動で進め、連続する状態間でドローンを滑らかに移動させ、半透
明パネルに現在のターンと配達済みドローン数を表示します。白い縁取りと固定された星空の背景
により、遊び心のある見た目を保ちながらマップを読みやすくします。これにより、ネットワーク
構造、同時移動、待機、restrictedゾーンへの移動を理解しやすくします。restrictedゾーンは
常にオレンジ色に発光し、ドローンがrestrictedゾーンへ向かって移動している間、その接続も
発光します。ゾーンの色には、Pygameが色名を認識できる場合、マップの`color`メタデータを
使用します。認識できない色名の
場合、開始ハブは緑色、終了ハブは黄色、その他のゾーンは灰色で代用します。

ビジュアライザーの操作方法：

- `Space`：再生または一時停止
- `Right Arrow`：1ターン進めて一時停止
- `Left Arrow`：1ターン戻って一時停止
- `R`：ターン0へ戻る
- `Esc`：ビジュアライザーを閉じる

### 開発用コマンド

```bash
make test
make lint
make lint-strict
make debug MAP=sample_map.txt
make clean
```

`make lint`は必須のflake8とmypy検査を実行します。`make lint-strict`は、より厳格なmypy設
定を使用します。`make clean`は生成されたキャッシュとビルド成果物を削除しますが、仮想環
境は保持します。

## 入力形式

マップは正のドローン数で始まり、その後にゾーン定義と接続定義が続きます。

```text
nb_drones: 2
start_hub: start 0 0 [color=green]
hub: middle 1 0 [zone=normal color=blue max_drones=2]
end_hub: goal 2 0 [color=yellow]
connection: start-middle [max_link_capacity=2]
connection: middle-goal [max_link_capacity=2]
```

メタデータは任意です。通常ゾーンのデフォルトは`zone=normal`、`color=none`、
`max_drones=1`です。接続のデフォルトは`max_link_capacity=1`です。行には`#`で始まるコメ
ントを含められます。

## 期待される出力

出力の各行が1シミュレーションターンを表します。そのターンに移動するドローンだけが出力さ
れます。

```text
D1-middle D2-middle
D1-goal D2-goal
```

通常移動は`D<ID>-<zone>`と表示されます。restrictedゾーンへ入る2ターン移動の1ターン目
は、接続を`D<ID>-<source>-<destination>`として表示します。次のターンに目的ゾーンを表示
します。待機中のドローンは、そのターンの出力から省略されます。

## アルゴリズムの説明

### 1. パースとグラフ構築

`Parser`はマップを上から順に読み込みます。ドローン数、ゾーンの役割、座標、メタデータ、容
量、名前の重複、無向接続の重複、未定義ゾーンへの参照を検証します。パースしたデータは独自
の隣接リストグラフへ変換され、外部のグラフライブラリは使用しません。

### 2. 予約なし最短経路

`PathFinder`はDijkstra法を使用し、予約を考慮しない最短経路を計算します。辺のコストは移動
先ゾーンに基づき、normalまたはpriorityゾーンは1ターン、restrictedゾーンは2ターンです。
blockedゾーンは除外されます。移動コストが同じ経路では、より多くのpriorityゾーンを含む経
路を優先します。

この最初の結果は、複数ドローンのプランナーが使用する、予約なしの最小移動時間を提供しま
す。

### 3. 時間を考慮した経路計画

`PathPlanner`は、ID 1から順にドローンを1機ずつ計画します。各ドローンについて、
`ReservationPathFinder`が`(zone, turn)`で表される状態を探索します。状態からは、1ターン
の待機または隣接ゾーンへの移動を生成できます。候補を受け入れる前に、プランナーは到着ター
ンの目的ゾーン容量と、横断ターンの無向接続容量を確認します。

移動先がrestrictedの場合は2ターン移動になります。ドローンは中間ターンに接続を占有し、
その次のターンにrestrictedゾーンへ到着しなければなりません。接続上で待機することはできま
せん。

完成経路が見つかると、`ReservationTable`がそのゾーンと接続の全利用を予約します。そのた
め、後のドローンは先に計画されたドローンが使用する容量を避けて探索します。この処理は、待
機、重複する経路、複数の利用可能な経路、容量無制限の開始・終了ハブを処理します。

これは優先順位付きの逐次計画方式です。提供マップに対して有効で高速な解を生成しますが、後
のドローンを考慮した後に先のドローンの経路を再計画しないため、あらゆるマップで全体の最小
ターン数を数学的に保証するものではありません。

### 4. シミュレーション出力

`Simulation`は、計画された時間付き経路をターンごとの状態へ変換します。各状態には、移動文
字列、ドローン位置、ゾーン使用数、接続使用数、配達済みドローン数が含まれます。通常コマン
ドは課題形式で必要な移動文字列だけを出力し、すべてのドローンが終了ハブへ到着した後に停止
します。

## プロジェクト構成

- `fly_in.py`：コマンドラインの入口と処理全体の接続
- `read_map.py`：入力パーサーと検証
- `models.py`：共有データモデルと型エイリアス
- `graph.py`：独自グラフ表現と移動コスト
- `pathfinding.py`：予約なし最短経路
- `reservation_pathfinder.py`：1機分の時間付き経路探索
- `reservation_table.py`：ゾーンと接続の容量予約
- `path_planner.py`：全ドローンの計画と予約
- `simulation.py`：ターンごとの状態生成と課題指定出力
- `visualizer.py`：Pygameイベントループとターン再生操作
- `renderer.py`：接続、ゾーン、ドローン、状態表示の拡縮可能な描画
- `tests/`：パーサー、経路探索、予約、シミュレーション、マップのテスト

## 設計上の判断と制限

- 接続は、移動と容量の両方で無向として扱います。
- 容量は、グラフを変更するのではなくターン単位で予約します。
- 開始・終了ハブは`max_drones`を無視し、容量無制限です。
- 待機は、次のターンに同じゾーンを繰り返すことで表現します。
- 1機ずつ計画することで、実装を理解しやすく決定的にしていますが、結果が全体最適になる保証
  はありません。
- グラフィカル表示は、ゾーン間でドローン位置を連続補間するのではなく、離散的なターン状態
  をアニメーション表示します。
